# Repository ports return entities, not DTOs

The CatalogRepository and LySourceRepository ports (JSDoc typedefs in `js/application/ports/`) return domain objects — `Collection`, raw `.ly` strings — never raw JSON rows. Concrete adapters (JsonCatalogRepository, FileLySourceRepository, HacklilyScoreRenderer) own the raw data shapes and normalize slugs (`row.slug || slugify(row.name)` inside the adapter) before constructing entities. This keeps the port contract stable when the JSON source is later swapped for a backend (SQL/API): only the adapter changes, nothing upstream is rewritten. Rejected alternative: returning DTOs across the boundary — that would freeze the JSON row shape into the contract and force a shared DTO→entity mapper in the application layer.
