# Ports are abstract base classes, not JSDoc typedefs

The three ports (CatalogRepository, LySourceRepository, ScoreRenderer) were pure JSDoc `@typedef` contracts in `js/application/ports/` — type-only, checked at runtime only by a duck-typing helper (`assertImplements`) in the composition root. They are now abstract base classes: the base class's constructor refuses direct instantiation via a `new.target` guard, it declares `@abstract` stub methods that throw if a subclass fails to override them, the adapters extend the base (`JsonCatalogRepository extends CatalogRepository`, `FileLySourceRepository extends LySourceRepository`, `HacklilyScoreRenderer extends ScoreRenderer`), and the composition root validates wiring with `instanceof` instead of `assertImplements`. Rationale: the typedef-plus-duck-typing indirection was unfamiliar and hard to read, while abstract-class-plus-extends reads like the interface hierarchy of the planned TypeScript migration — and since an abstract class is already a valid JSDoc type, the use cases' `@typedef {import(...)}` references kept working unchanged. Enforcement is threefold: the `new.target` guard fails at construction, the throwing stubs fail at call time when an override is missing, and `instanceof` fails fast at boot on wrong wiring. Rejected alternatives: keeping the typedefs alongside the classes (two sources of truth for one contract), construct-time override validation inside the base constructor (more ceremony than the `assertImplements` helper it would replace), and enabling `@ts-check` (repo constraint: no tooling).
