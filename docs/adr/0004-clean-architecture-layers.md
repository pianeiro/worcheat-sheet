# Clean Architecture layers as OOP classes

The inner layers were originally functional — entities were factory functions returning frozen plain objects (`createPiece`, `createArtist`), and use cases were plain functions with call-time dependency injection (`renderScore(deps, artistSlug, pieceSlug)`). To ready the codebase for the planned Node/React + TypeScript migration, domain, application, and infrastructure were converted to OOP: entities with identity and behavior (Piece/Artist/Collection, frozen at construction, queries as Collection methods), use case classes with constructor DI and an `execute()` method, and infrastructure as concrete adapter classes implementing JSDoc-typed ports. The presentation layer (presenters, views, components) intentionally stays functional — it maps 1:1 onto React components and hooks, and class-ifying it would be throwaway work before the migration; only the route controller became a class (`RouteController`) since it is the wiring point for dependencies.
